Foundational Concepts

Theoretical Framework & Dual Representations

Understanding how connections between two distinct sets are defined mathematically and represented in data structures.

1

Cartesian Product ($A \times B$)

Given two sets $A$ and $B$, their Cartesian product $A \times B$ is the set of all ordered pairs $(a, b)$ where $a \in A$ and $b \in B$.

$$A \times B = \{(a,b) \mid a \in A \land b \in B\}$$

Cardinality rule: $|A \times B| = |A| \cdot |B|$.

2

Binary Relation ($R \subseteq A \times B$)

A binary relation $R$ from $A$ to $B$ is a subset of $A \times B$. If $(a,b) \in R$, we write $a R b$, meaning element $a$ is related to $b$.

$$R \subseteq A \times B \quad \text{where} \quad a R b \iff (a,b) \in R$$

Total unique relations from $A$ to $B$ is $2^{|A| \cdot |B|}$.

3

Domain, Codomain, Range

The Domain is set $A$. The Codomain is set $B$. The Range (or Image) is the actual set of elements in $B$ that are assigned by $R$.

$$\text{Ran}(R) = \{b \in B \mid \exists a \in A, (a,b) \in R\}$$

The Range is always a subset of the Codomain: $\text{Ran}(R) \subseteq B$.

4

Matrix Representation ($M_R$)

A binary relation $R$ can be represented as a boolean matrix $M_R$ of dimension $|A| \times |B|$ where entry $m_{ij} = 1$ if $(a_i, b_j) \in R$, else $0$.

$$M_{ij} = \begin{cases} 1 & \text{if } (a_i, b_j) \in R \\ 0 & \text{otherwise} \end{cases}$$

Matrix operations allow fast relational composition & graph algorithms.

5

Bipartite Digraph View

Visualized as a directed bipartite graph with vertices partitioned into two disjoint sets $V_1 = A$ and $V_2 = B$, with directed edges going strictly from $A \to B$.

$$G = (A \cup B, E), \quad E = \{(a,b) \mid (a,b) \in R\}$$

In-degree & out-degree indicate injection and surjection properties.

6

Relational Database Mapping

In SQL RDBMS design, a binary relation between distinct entity sets $A$ and $B$ corresponds directly to a junction table with composite primary keys.

PRIMARY KEY (a_id, b_id)

Foreign keys enforce referential integrity to entity tables $A$ and $B$.

Concrete Applications

3 Detailed Worked Examples

Step-by-step transformations from discrete math sets to database implementation schemas.

Example 1

Student-Course Enrollment

Many-to-Many ($S \times C$)

Set Definitions:

$S = \{\text{Alice, Bob, Charlie}\}$

$C = \{\text{CS101, MATH202, PHYS301}\}$

Relation Rule $R$:

"Student $s$ is enrolled in Course $c$"

$R = \{(\text{Alice, CS101}), (\text{Alice, MATH202}), (\text{Bob, CS101}), (\text{Charlie, PHYS301})\}$

SQL Junction Schema:

CREATE TABLE Student_Courses (
  student_id VARCHAR(20),
  course_code VARCHAR(20),
  PRIMARY KEY (student_id, course_code),
  FOREIGN KEY (student_id) REFERENCES Students(id),
  FOREIGN KEY (course_code) REFERENCES Courses(code)
);
Example 2

Numerical Divisibility

Arithmetic Relation ($a \mid b$)

Set Definitions:

$A = \{2, 3, 4\}$

$B = \{4, 6, 8, 9, 12\}$

Relation Rule $R$:

"a divides b ($b \pmod a = 0$)"

$R = \{(2,4), (2,6), (2,8), (2,12), (3,6), (3,9), (3,12), (4,4), (4,8), (4,12)\}$

Cartesian Reduction:

$|A \times B| = 3 \times 5 = 15$ potential pairs. $|R| = 10$ active relations. Matrix density: $\frac{10}{15} \approx 66.7\%$.

Example 3

E-Commerce User Purchases

User to Product Mapping ($U \times P$)

Set Definitions:

$U = \{\text{U101, U102, U103}\}$

$P = \{\text{Laptop, Phone, Headphones}\}$

Relation Rule $R$:

"User $u$ has purchased Product $p$"

$R = \{(\text{U101, Laptop}), (\text{U101, Phone}), (\text{U102, Headphones})\}$

Range & Inactivity Analysis:

$\text{Dom}(R) = \{\text{U101, U102}\}$ (U103 inactive).
$\text{Ran}(R) = \{\text{Laptop, Phone, Headphones}\} = P$ (Surjective).
